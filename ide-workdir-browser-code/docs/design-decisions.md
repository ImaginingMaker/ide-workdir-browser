# 设计规范统一记录

实现以 `docs/PRD.md` 为产品真源，并参考 OpenPencil 设计资产。发现冲突时采用以下统一规则。

## 布局

| 项目            | 统一规范                                                       |
| --------------- | -------------------------------------------------------------- |
| 最小窗口        | 900 × 540px                                                    |
| 标题栏 / 工具栏 | 均为 44px                                                      |
| 侧边栏          | 220px；窗口不超过 720px 时收为 48px 图标栏                     |
| Inspector       | 256px；窄窗自动隐藏                                            |
| 内容区          | 最小 256px                                                     |
| 路径栏          | 内容区下方 30px，完整路径水平滚动                              |
| 搜索框          | 工具栏居中；标准 360–560px，中窗 300px，窄窗 220px，最小 160px |
| 工具栏          | 强制裁剪溢出，操作组不可压缩                                   |

原设计 token 中的 52px 工具栏和 480px 预览宽度未采用，统一为 PRD 的 44px 与 256px。
旧 `560 × 420px` 最小窗口无法同时容纳 `220px` 侧边栏、`256px` 内容区和 `256px` Inspector。
`760px` 虽满足面板宽度，但工具栏左侧会被对称 Grid 列裁剪；最终采用 `900 × 540px`，并在
`150%` UI 缩放下验证工具栏、路径栏和状态栏无溢出。
Inspector 收起时保持组件挂载，但不得在主内容区留下残余布局占位或无意义横向滚动条；普通
文件区只允许纵向滚动，Finder 风格分栏视图保留自身横向滚动。

## 信息架构

- 文档内容、图片大图和二进制预览归主工作区并通过工具栏下方的多文档标签切换；Inspector 保留图片缩略图和元数据；标签和预览状态按 Agent 隔离。
- Markdown 渲染支持 GFM 与 Mermaid fenced code block；源码和常见配置/代码文件使用彩色语法高亮，JSON/JSONC 在展示层格式化。
- 搜索结果使用主内容区工作台，不使用小浮层。
- 设置是独立工作台，不渲染浏览导航、视图切换、搜索、统计或刷新。
- 关于页承载应用版本、手动稳定版检查和快捷键参考；更新检查不在启动时自动执行。
- 每个 Agent 独立保存路径、历史、视图、选择、搜索和 Inspector 状态。
- 产品范围固定为 10 个默认 Agent：Codex、Claude Code、Cursor、Zed、Trae、VS Code、
  Gemini CLI、OpenCode、Windsurf 和 Kiro；不采用旧 HTML 中的 4 Agent 口径。

## 视觉与可访问性

- 品牌强调只使用一个 `--primary`；绿、黄、红仅承担成功、警告和错误语义。
- 浅色和深色均使用语义 Sass token，组件中不散落主题颜色。
- 图标按钮提供 `aria-label`、可见焦点环和按压状态。
- 文件类型使用统一语义图标映射；文件夹提供线框、实心、双色三套全局预设并在外观设置中切换。
- 视图切换使用 `tablist/tab` 与 `aria-selected`。
- 连接状态同时提供文字和颜色，不依赖色点。
- 长文件名在图标视图限制为两行，列表和路径使用单行截断及 tooltip。

## 行为

- 不申请完全磁盘访问权限；桌面、文稿等受保护位置由 macOS 按目录提示授权，遵循最小权限原则。
- 用户拒绝目录访问时只隔离对应 Agent，并提供重新尝试、更改工作目录和固定的“文件与文件夹”
  系统设置入口。
- 已拒绝的 Agent 在应用重新获得焦点后静默复检；其他 Agent 的目录、选择和搜索状态不受影响。
- 设置统一采用自动保存；保存失败通过全局错误层反馈。
- 移到废纸篓作为受控破坏性操作开放：必须先二次确认，默认聚焦取消，主进程校验 Agent
  入口路径，拒绝 Agent 根目录和通过符号链接目录触达的外部真实目标；永久删除、新建和重命名仍不暴露入口。
- 文件系统请求不能信任 Renderer 输入；主进程校验用户入口路径必须位于工作目录树下。
- 工作目录内的所有子入口均放行。符号链接即使指向工作目录外部，也可通过该入口浏览和预览。
- 对符号链接入口执行移到废纸篓时，只移动链接入口本身，不删除链接目标。
- 搜索默认不递归符号链接目录；开启“跟随符号链接”后才递归，降低循环扫描风险。
- 更新检查由 Main Process 匿名访问构建时注入的 GitHub `releases/latest`；Renderer 只获得
  类型化状态，不接触网络、仓库配置或原始响应。
- Release URL 必须通过 HTTPS 主机和同仓库路径 allowlist，随后复用窗口服务交给系统浏览器。
- 当前未签名构建只允许检查和跳转下载；自动下载、安装和启动检查在 Developer ID 签名与
  notarization 完成前不开放。

## 测试与文档

- Vitest 负责服务、共享契约、状态和组件行为；Computer Use 负责真实窗口、原生快捷键、鼠标、
  可访问性树、响应式布局和 Electron 运行时回归。
- `npm run check` 同时承担隐私扫描、版本一致性、格式、Lint、类型和覆盖率门禁；Git
  pre-commit hook 复用同一套提交前检查。
- GitHub CI 对 Pull Request 和 `main` 执行检查与生产 Bundle 构建；Release workflow 默认
  dry-run，正式发布使用 Bot 身份、原子推送版本提交和 Tag，并拒绝覆盖已有 Release。
- Computer Use 用例统一维护在
  [computer-use-regression.md](computer-use-regression.md)，并按正向、边缘、负向分类。
- 桌面回归失败必须保留为失败用例并关联缺陷，不能通过降低预期或删除记录使验收通过。
- 同一 Bundle ID 的开发实例与生产预览不能同时作为被测应用，避免窗口选择和可访问性树混淆。
- 任意产品文档发生变化时，必须检查 PRD、设计决策、回归用例、根 README、代码 README 和
  `AGENTS.md` 是否需要同步。

## 原型问题处理

原设计验证报告中的 12 个 DOM 映射问题属于 HTML 原型元数据，不复制到 React 实现：

- 右键菜单动作将使用真实 React 事件和类型化命令，不依赖 `data-dom-id`。
- 设置页不注册浏览器搜索和统计交互。
- 旧 Tailwind 命名颜色和页面内硬编码色被 Sass token 替代。
